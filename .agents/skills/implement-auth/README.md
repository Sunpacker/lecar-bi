## implement-auth.md - создан gpt-6-astra с high effort:

1. **Итоговая структура**

```text
implement-auth/
├── SKILL.md                     # 73 строки: workflow, решения, инварианты, DoD
├── agents/openai.yaml
└── references/
    ├── oauth-identities.md       # OAuth/OIDC, providers, identities, linking
    └── verification.md           # Тесты, окружение, критерии завершения
```

2. **Что перенесено из проекта**

Серверная проверка прав и владения ресурсами, отзыв сессий, атомарность операций, безопасные редиректы, тестирование отказов, проверка конфигурации и окружения. Обнаруженные слабые места преобразованы в запреты и негативные сценарии проверки.

3. **Что намеренно не переносилось**

Nuxt/NestJS, TypeORM, Vitest, DDD-структура каталогов, локальные роли и bootstrap-флаг, ограничения email-доменов, конкретные маршруты и сроки действия. Также исключены автоматическая привязка по email, клиентская проверка state как единственная защита backend и JavaScript-readable credential cookies.

4. **Почему skill остаётся stack-agnostic**

Он требует сначала исследовать проект и выбрать существующие механизмы. Не навязывает JWT, ORM, frontend, отдельный auth-сервис или архитектурные слои. Проверки определяются по инструментам проекта; для интерпретируемых языков предусмотрен эквивалент production build.

Валидатор skill-creator, форматирование и проверка ссылок проходят. Независимый сценарный review охватил **TypeScript, PHP, Python и Go**; найденные неоднозначности CSRF callback и сроков отзыва исправлены. Это проверка инструкций, не запуск четырёх приложений.

OAuth/OIDC сверены с [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html),и [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html).
