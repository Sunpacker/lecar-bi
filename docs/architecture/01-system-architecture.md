# 01. System Architecture

## Основные компоненты

Система состоит из нескольких логических уровней:

- браузер пользователя;
- web-сервис на Next.js;
- backend-сервис аналитики на Laravel;
- PostgreSQL как основное постоянное хранилище;
- Redis для кэша, очередей, блокировок и технических задач;
- будущие внешние или внутренние микросервисы.

## Ответственность Next.js

Next.js отвечает за:

- пользовательский интерфейс;
- маршрутизацию;
- серверный и клиентский рендеринг;
- интерактивные dashboard;
- таблицы, фильтры и визуализации;
- frontend-specific state;
- работу пользовательской сессии;
- обращение к backend API;
- при необходимости — роль тонкого BFF.

Next.js не должен становиться местом хранения бизнес-правил аналитики.

## Ответственность Laravel

Laravel отвечает за:

- бизнес-правила;
- расчёт аналитических показателей;
- работу с доменными сущностями и value objects;
- оркестрацию use cases;
- хранение данных;
- построение read models;
- импорт данных;
- фоновые задачи;
- интеграционные события;
- правила alerting;
- подготовку API для frontend и других сервисов.

## Граница между frontend и backend

Связь между Next.js и Laravel должна строиться через явный API-контракт.

Frontend не должен зависеть от внутренней структуры PHP-классов, ORM-моделей или деталей хранения данных.

Backend не должен зависеть от конкретных UI-компонентов frontend.

## Независимость deployable-сервисов

Next.js и Laravel должны:

- иметь независимые процессы сборки;
- иметь независимые Docker images;
- иметь независимые конфигурации окружения;
- иметь возможность разворачиваться отдельно;
- взаимодействовать только через согласованные контракты.

## Развитие системы

При росте проекта отдельные доменные или инфраструктурные области могут выделяться в самостоятельные сервисы.

Выделение должно происходить только при наличии причины, например:

- отдельный масштаб нагрузки;
- отдельная команда;
- независимый жизненный цикл;
- специфическая технология;
- чёткая бизнес-граница;
- необходимость отдельного SLA.
