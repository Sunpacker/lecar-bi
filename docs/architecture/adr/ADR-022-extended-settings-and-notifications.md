# ADR-022: Расширенные «Настройки», приглашения по email и персональные уведомления

## Статус

Принято (2026-09-25)

## Контекст

Ранее платформа AutoBI предоставляла только базовое управление ролями участников на странице `/settings/access` и переключение темы в браузере. Отсутствовали:
- Возможность редактирования личного профиля (имени) и смена пароля с отзывом активных сессий;
- Переименование рабочего пространства владельцем;
- Приглашение новых участников по email со ссылкой, сроком действия и выбором роли;
- Персональные статусы прочтения уведомлений и персональные настройки важности (`info`, `warning`, `critical`).

## Решение

### 1. Архитектура настроек на Frontend
- Сайдбар: пункт «Настройки» (`/settings`) активирован, бейдж «Скоро» удалён, отдельный пункт «Доступ» удалён из корневой навигации (перенесён во вкладку настроек). Раздел подсвечивается на всех дочерних маршрутах `/settings/*`.
- Общая оболочка `SettingsLayout` (`frontend/app/(dashboard)/settings/layout.tsx`) с поднавигацией по вкладкам:
  - `/settings` — Профиль (имя, email только для чтения) и Оформление (светлая, тёмная, системная темы с сохранением в `autobi-theme`);
  - `/settings/security` — Смена пароля (текущий, новый, подтверждение) с предупреждением об отзыве сессий и перенаправлением на `/login?reason=password_changed`;
  - `/settings/workspace` — Название пространства (редактирование доступно только владельцу с capability `workspace.settings.manage`), slug только для чтения;
  - `/settings/access` — Управление участниками, смена ролей с защитой последнего владельца, список ожидающих приглашений (повторная отправка, отзыв) и модальное окно приглашения;
  - `/settings/notifications` — Персональные предпочтения уровней важности для выбранного пространства.

### 2. Приглашения в рабочее пространство
- Хранение в PostgreSQL (`invitations`), поля: `id`, `workspace_id`, `email`, `role` (`member` | `viewer`), `status` (`pending`, `accepted`, `cancelled`), `token_hash`, `expires_at`, `created_at`.
- Токен ссылки одноразовый (срок 7 дней). В БД сохраняется только SHA-256 хеш.
- Отправка email через очередь `mail` Laravel Mail (`WorkspaceInvitationMail`, `SendWorkspaceInvitationEmailJob`).
- Запуск фонового воркера: `php artisan queue:work redis --queue=default,mail --tries=3`.
- Публичный маршрут принятия: `/invite/[token]`. Отображает детали без авторизации; для зарегистрированного пользователя — кнопка принятия, для нового — форма ввода имени и пароля. Создание аккаунта, привязка к воркспейсу и выпуск сессионного токена выполняются атомарно.

### 3. Центр уведомлений и персональные настройки
- Страница `/notifications`: пагинация, фильтрация по непрочитанным и уровням важности, отметка отдельного уведомления как прочитанного, снапшот-операция «Прочитать всё» (`up_to_notification_id`).
- Шапка: компонент `NotificationBell` со счётчиком непрочитанных, обновляемый при загрузке, возврате фокуса и раз в 30 секунд при активной вкладке.
- Персональные таблицы в БД Notification: `notification_reads` (user_id, notification_id, read_at) и `notification_preferences` (user_id, workspace_id, info, warning, critical).
- Межсервисное взаимодействие: Next.js BFF proxy проверяет сессию и права, после чего обращается к Notification Service с заголовками `X-Server-Secret`, `X-User-Id`, `X-Workspace-Id`. При сбое Notification Service клиент BFF возвращает graceful fallback, исключая блокировку аналитики.
