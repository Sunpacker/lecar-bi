# Storybook: каталог UI, готовые композиции и внедрение на экране продаж

## Результат

Подключить Storybook к существующему frontend: каталог всех 14 UI-модулей, переиспользуемые BI-компоненты и формы с интерактивными примерами. Применить новые абстракции на экране аналитики продаж.

Сохранить текущий визуальный стиль, светлую и тёмную темы. Storybook должен работать самостоятельно, без backend и авторизации.

## 1. Подключение Storybook

- Использовать `@storybook/nextjs-vite` — рекомендуемую интеграцию для Next.js из [официальной документации](https://storybook.js.org/docs/get-started/frameworks/nextjs-vite).
- Добавить конфигурацию в `frontend/.storybook/`, команды `storybook` на порту 6006, `build-storybook` и `test:storybook`.
- Зафиксировать совместимые стабильные версии зависимостей в npm lockfile; проверить совместимость с существующими Next.js 16, React 19, Vitest 5 и Node.js 22.
- Подключить существующие глобальные стили, Tailwind/PostCSS, алиас `@/`, шрифт Geist и статические ресурсы. Не импортировать корневой layout приложения.
- Добавить Docs, Controls, Accessibility и переключение темы. Применять тему к корню preview-документа, чтобы Select и Sheet в порталах отображались корректно.
- Исключить `storybook-static` и результаты браузерных тестов из Git, форматирования и lint.

## 2. Каталог существующих компонентов

Разместить типизированные CSF stories рядом с исходными компонентами в `frontend/components/ui/`. Существующие реализации импортировать напрямую.

| Раздел | Компоненты и примеры |
|---|---|
| Основные | Button и Badge: все варианты и размеры, иконки, disabled для кнопок |
| Поля | Input, Label, Field: подписи, подсказки, ошибки, disabled, адаптивное расположение |
| Формы | Form: React Hook Form, валидация, отправка и сообщения об ошибках |
| Выбор | Select: placeholder, выбранное значение, группы, disabled, управление с клавиатуры |
| Контейнеры | Card, Separator: составные части, размеры и ориентация, поддерживаемые реализацией |
| Данные | Table: заголовки, строки, footer, пустой результат и горизонтальная прокрутка |
| Графики | Chart: линия и столбцы, tooltip, legend, несколько серий |
| Обратная связь | Progress и Skeleton: прогресс и примеры загрузки |
| Панели | Sheet: стороны открытия, заголовок, описание, закрытие и возврат фокуса |

Для каждого модуля предоставить документацию назначения, импортов и рабочего JSX-примера. Вложенные компоненты показывать в составе корректной композиции с необходимым контекстом.

## 3. Готовые абстракции

Разместить новые компоненты в `frontend/src/shared/ui/`, экспортировать через существующий публичный index. Stories организовать в разделах `UI`, `Compositions/BI`, `Compositions/Forms`.

| Компонент | Публичный контракт |
|---|---|
| `MetricCard` | Заголовок, готовое отображаемое значение, описание, необязательное действие и состояние загрузки |
| `FilterBar` | Поля через `children`, область действий, callback сброса и disabled |
| `DataTable<T>` | Строки, типизированные колонки с render-функциями, ключ строки, управляемые сортировка и пагинация с callbacks |
| `ChartCard` | Заголовок, описание, действия и область графика; использует существующий `ChartContainer` |
| `EmptyState`, `ErrorState`, `LoadingState` | Текст, необязательное действие; для загрузки — доступное описание и настраиваемый skeleton |
| `TextField` | Input с подписью, подсказкой и ошибкой; стандартные input props и ref |
| `SelectField` | Select с подписью, подсказкой, ошибкой, списком options и управляемыми value/onValueChange |
| `FormSheet` | Управляемое открытие, заголовок, описание, поля, submit/cancel, submitting и ошибка отправки |

Правила реализации:

- Композиции собираются из имеющихся UI-примитивов и используют текущие дизайн-токены.
- Shared-компоненты не импортируют API-типы продаж, gateway или feature-модули. Получают данные и callbacks через props.
- `DataTable` отображает переданную страницу данных; сортировка и получение страниц остаются у вызывающего кода. Новую табличную библиотеку не добавлять.
- Поля работают самостоятельно и через `Controller` существующего React Hook Form. Схемы валидации принадлежат конкретной форме.
- `FormSheet` не закрывается самостоятельно после submit: вызывающий код управляет результатом и открытием.
- Все примеры используют фиксированные демонстрационные данные. Для форм показать локальную валидацию, успешную отправку и ошибку.

## 4. Внедрение в аналитику продаж

- Перевести карточки показателей на `MetricCard`, фильтры на `FilterBar`, `TextField` и `SelectField`, таблицу детализации на `DataTable`, оболочку графика на `ChartCard`.
- Использовать общие состояния загрузки, ошибки и отсутствия данных.
- Сохранить публичные props существующих Sales-компонентов, форматирование значений, статусы, API-запросы, URL-параметры, сброс страницы и взаимодействия графиков.
- Преобразование API-пагинации, определения колонок и оформление статусов оставить в модуле продаж.
- Для новых полей выбора сохранить смысл «Все категории / Все регионы», доступные названия и клавиатурное управление.
- `FormSheet` показать в Storybook; новую форму на экране продаж не добавлять.

## 5. Проверки и критерии приёмки

- Добавить отдельную браузерную конфигурацию Storybook через Vitest addon и Playwright Chromium; существующий запуск unit-тестов сохранить.
- Проверить рендер stories в обеих темах. Добавить interaction-тесты для выбора значения, открытия/закрытия Sheet, валидации формы, сортировки, пагинации, сброса фильтров и повторного действия после ошибки.
- Сохранить и актуализировать тесты продаж; проверить фильтрацию, drill-down, URL-состояние, форматирование и границы пагинации.
- Проверить узкий экран, длинные подписи, пустые данные, disabled, фокус и доступные имена элементов.
- Выполнить lint, format-check, typecheck, существующие тесты, `test:storybook`, сборки Next.js и Storybook.
- Добавить сборку и браузерные тесты Storybook в frontend CI. Обновить README и профильные документы frontend/testing, сохранив уже имеющиеся пользовательские изменения.

Готовность: все 14 модулей представлены в каталоге, композиции доступны для импорта, экран продаж использует их без функциональных регрессий, проверки проходят.

Публикация Storybook, Chromatic, перенос остальных экранов и изменение backend/API в эту работу не входят. На этапе подготовки плана файлы не изменялись, тесты не запускались.
